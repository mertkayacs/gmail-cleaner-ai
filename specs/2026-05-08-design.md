# Gmail Triage System, design

**Date:** 2026-05-08
**Status:** approved design, pre-implementation
**Author:** Mert Kaya
**Audience:** Mert, Reeves (CC, Codex, Gemini variants)

## Goal

A working triage system across all of Mert's Gmail accounts. After setup, the inbox shows only mail that genuinely needs attention. Newsletters, marketing, automated notifications, and receipts auto-route to dedicated labels and skip the inbox. Whatever lands in the inbox is small enough to triage manually or via Opus on demand.

## Non-goals

- Permanent deletion. Trash is the terminal action; Gmail's 30-day auto-purge handles permanent removal.
- Per-mail AI runtime on every incoming mail. Filters do the bulk on arrival, no compute.
- Cross-account unified view. Each Gmail keeps its own labels and filters; the system is replicated, not unified.
- Email composition or reply automation.

## Architecture

Two layers:

1. **Gmail filters (the 80%).** Configured once per account. Auto-route incoming mail by sender pattern, header presence, Gmail category, and subject keywords. Apply labels, skip inbox. Zero compute, runs forever.

2. **Opus on demand (the 20%).** A `/gmail-triage` skill at `~/.claude/skills/gmail-triage/`. Mert invokes it when the inbox needs cleanup. Opus reads the remaining mail's metadata, classifies by life-area and action signal, applies labels, moves junk to Trash. Initial backend: existing `mcp__claude_ai_Gmail__*` tools (single account, primary). Multi-account upgrade: install workspace-mcp via uvx (paused install, pre-scaffolded).

Mail flow: incoming → Gmail filter pass → either skipped to a label (out of inbox) or lands in inbox → Opus pass on demand → labeled and dispositioned.

## Label tree

Labels are per-account (Gmail constraint). Same tree replicated across each Gmail account.

```
Personal/        Family · Friends · Wedding
Work/            Enocta · Other
Academic/        UBMK-2026 · Frontiers · Papers · Conferences · Reviewers
Learning/        German · Courses · Books
Finance/         Banking · Receipts · Tax
Move-Germany/    Visa · Housing · Logistics
Skim/            Newsletters-Tech · Newsletters-Other · Updates
Junk/            Promo · Notifications
Reference/       Receipts · Shipping · Confirmations
Important        (Gmail's built-in label, also auto-applied by filters for banks/security)
```

Naming convention: `Parent/Child` is Gmail's nested-label syntax. Sub-labels can be added later by the Opus pass when patterns emerge (a new conference acronym, a recurring sender from a service Mert uses).

## Filter rules

Each row is one Gmail filter. "Skip inbox" means apply "Skip Inbox (Archive it)" plus the label. Order matters when filters chain; Gmail evaluates each filter independently and applies all matches.

| # | Matcher (Gmail search syntax) | Action |
|---|---|---|
| 1 | `category:promotions list-unsubscribe` | label `Junk/Promo`, skip inbox |
| 2 | `category:promotions` (no unsubscribe header) | label `Junk/Promo`, skip inbox |
| 3 | `from:(*noreply* OR *no-reply*) -from:(<bank-list> OR <security-domain-list>)` | label `Junk/Notifications`, skip inbox |
| 4 | `list-unsubscribe` AND `has:nouserlabels` AND not in newsletter-allowlist | label `Skim/Newsletters-Other`, skip inbox |
| 5 | `subject:(receipt OR invoice OR confirmation OR shipping OR tracking)` | label `Reference/Receipts`, skip inbox |
| 6 | `from:(@paypal.com OR @stripe.com OR <bank-list>)` | label `Finance/Banking`, label `Important`, never skip inbox, star |
| 7 | `subject:(verification OR 2FA OR "two-factor" OR "password reset" OR OTP)` | label `Important`, star, never skip inbox |
| 8 | `from:*@github.com -from:noreply@github.com` | label `Work/Other`, do not skip inbox |
| 9 | `category:social` | label `Skim/Updates`, skip inbox |
| 10 | `category:forums` | label `Skim/Updates`, skip inbox |

Notes:
- Gmail's filter UI restricts to fields From / To / Subject / Has the words / Doesn't have / Size / Has attachment / Categorize. Use "Has the words" for non-trivial syntax (`list-unsubscribe`, `has:nouserlabels`, `category:promotions`). Use From for sender patterns. Use Subject for keyword matches. Combinators (AND, OR, parens, leading `-` for NOT) only work inside "Has the words".
- The `list-unsubscribe` matcher relies on Gmail recognizing the standard `List-Unsubscribe` header. Most legitimate bulk senders include it.
- Mert can extend per account before importing. The XML is a starting set, not exhaustive.
- Existing `/gmail-triage` SKILL.md uses `AI-Triage/Junk` as the parent label. During implementation, update SKILL.md to align with this spec's `Junk/*` convention.

## Opus role and skill behavior

The `/gmail-triage` skill at `~/.claude/skills/gmail-triage/SKILL.md` runs the Opus pass.

Trigger phrases: "/gmail-triage", "triage gmail", "clean up my inbox", "process my mail".

Inputs to confirm at runtime: which account(s), how many mails this run, dry-run vs live.

Pipeline (per account):
1. Search the inbox for mail without `Skim`, `Junk`, `Reference`, or other auto-route labels (mail filters did not dispose of).
2. Read metadata in batches of ~100 (subject, sender, snippet, date, current labels).
3. Heuristic safelist (`whitelist.json`): senders, domains, subject keywords, Gmail labels that Opus must never override toward Junk.
4. Opus classifies the rest. Output per mail: category (`keep_personal`, `keep_work`, `keep_security`, etc., or `junk_*`), suggested sub-label, confidence, one-line reasoning.
5. If confidence on a `junk_*` category is below 70, treat as `keep_other`.
6. Apply: `keep_*` → add the sub-label, leave in inbox. `junk_*` → add `Junk/<sub>` label and add the `TRASH` system label.
7. Append to `~/jarvis/gmail-triage-log.md` (one line per mail: timestamp, account, message_id, subject, sender, category, action, reasoning).
8. Print per-account summary (X processed, Y kept, Z labeled, W trashed).

Safety rails: never permanent delete, whitelist is law, first run on any account is dry-run, audit log is append-only, when in doubt keep over trash, never include the email body in the classifier prompt (subject + sender + snippet only).

## Trash sweep (one-time per account, before filters take over)

Run these in Gmail web or mobile. Bulk-select results, move to Trash. Gmail's 30-day auto-purge handles permanent removal.

- `category:promotions in:inbox -is:starred`
- `from:noreply in:inbox -is:starred -is:important`
- `list-unsubscribe has:nouserlabels -is:starred`

These find unuseful mail by Gmail's own usefulness signals: `is:starred` means Mert cared, `is:important` means Gmail's classifier cared, `list-unsubscribe` signals bulk sender, `category:promotions` is Gmail's marketing detection.

Bulk-select procedure (Gmail web): run search, click the select-all checkbox at the top of results, click the banner "Select all conversations that match this search", then click the trash icon.

## Multi-account application plan

1. Choose the first account (primary recommended).
2. Create the label tree in Gmail UI: Settings → Labels → Create new label. Use `Parent/Child` syntax for nesting.
3. Import the filter XML: Settings → Filters and Blocked Addresses → Import filters → upload `filters.xml` → check "Apply new filters to existing email" → Create filters.
4. Run the trash sweep searches.
5. Replicate per remaining account:
   - Create the same label tree (Gmail UI, until a labels-creation script is built post-MCP).
   - Export filters from account #1 (Settings → Filters → Export), import into account #N.
   - Run trash sweep per account.
6. The `/gmail-triage` skill works against whichever account the active Gmail MCP can reach. Single account works today via `mcp__claude_ai_Gmail__*`. Multi-account requires the paused workspace-mcp install.

## Out of scope (this spec)

- Permanent deletion of Trash on demand. Gmail's 30-day auto-purge handles it.
- Email composition, drafting, sending.
- Notion or task-system integration.
- Cross-account unified view, duplicate detection.
- Filtering on body content (Gmail filter limit; subject, sender, headers, category only).

## Future expansion

- Add sub-labels as life accumulates new categories (Germany employer, conference acronyms, project codenames).
