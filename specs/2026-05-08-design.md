# Gmail Triage System, design (v2)

**Date:** 2026-05-08 (revised, v2 supersedes v1)
**Status:** approved design, implementation in progress
**Author:** Mert Kaya

## Goal

A debuggable Python program that inventories, classifies, and cleans up multiple Gmail accounts. Auto-generates the categorization (no manual lists from Mert). One account at a time.

## Architecture: single-file Python, IMAP, Anthropic API

Three subcommands:

1. **inventory** — IMAP read all mail metadata, compute stats. No LLM. Outputs `inventory.json` and `report.md`.
2. **analyze** — feed top senders plus sample subjects to Claude in batches. Outputs `proposed_categories.json`, `allowed.txt`, `disallowed.txt`.
3. **apply** — read the approved lists, IMAP modify (apply labels via Gmail's X-GM-LABELS extension, move disallowed to Trash). Has `--dry-run`.

Mail access via IMAP with Gmail App Passwords. Skips OAuth and GCP entirely.

## Data flow per account

```
.env (account email + App Password + ANTHROPIC_API_KEY)
   |
   v
triage.py inventory  -->  data/<account>/inventory.json
                          data/<account>/report.md

inventory.json
   |
   v
triage.py analyze    -->  data/<account>/proposed_categories.json
(Claude API)              data/<account>/allowed.txt
                          data/<account>/disallowed.txt

allowed.txt + disallowed.txt   (Mert reviews and edits)
   |
   v
triage.py apply      -->  IMAP changes (labels + Trash)
                          data/<account>/applied.log
```

## Classification taxonomy

The LLM proposes top-level categories from sender patterns. Standard categories:

- Keep: `keep_personal`, `keep_work`, `keep_security`, `keep_transactional`, `keep_calendar`, `keep_newsletter`, `keep_other`
- Junk: `junk_promo`, `junk_spam`, `junk_low_newsletter`, `junk_notification`, `junk_other`

Sublabels are dynamic strings (`Personal/Family`, `Work/<company>`, `Newsletter/Tech`, `Junk/Promo`). The LLM proposes; Mert can edit before apply.

## Safety

- Mail body never sent to Claude. Subject, sender, and sample subjects only.
- Trash is terminal, never permanent delete. Gmail's 30-day auto-purge handles permanent removal.
- `--dry-run` flag on `apply`.
- `allowed.txt` and `disallowed.txt` are plain text, editable before apply.
- Audit log in `applied.log` per account.

## Out of scope (this version)

- Continuous Gmail filter rules (deferred; can be derived later from learned senders).
- Per-incoming-mail real-time classification (deferred).
- Multi-account unified view.
- Email composition or sending.

## Implementation

Single-file Python program (`triage.py`). Around 300 lines. Dependencies: `anthropic`, `python-dotenv`. Uses stdlib `imaplib`, `email`, `argparse`.
